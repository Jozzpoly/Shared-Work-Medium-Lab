# Heterogeneous Shared Browser Probe — 2026-10-07

**Status:** EXPERIMENTAL FIXTURE · UNRUN · DRAFT-BRANCH ONLY · NOT PROJECT AUTHORITY

## Research question

Can two heterogeneous model conversations inhabit the **same ordinary browser environment** as a shared external world while retaining separate private conversational/model context?

This is not a benchmark of which model is better.

The stronger question is:

> can common environmental structure itself become a coordination / continuity substrate between different minds without direct context copying?

## Live capability precondition already observed

Browser ChatGPT currently has an Opera MCP connector exposing:
- open tabs;
- up to seven days of browser history;
- page/accessibility content;
- screenshots;
- URL navigation;
- tab close.

A live Claude Free account now also shows a connected custom **Opera** MCP server at:

`https://connector.mcp.opera.com/mcp`

Its connector settings expose the same broad tool classes:
- Browser history;
- Browser tabs;
- Screenshot;
- Tab/page content;
- Close tab;
- Go to page.

The Claude connector page exposes a **Disconnect** action, so this is stronger than a remembered setup attempt: the custom connector is currently configured.

However its tool policy currently requires approval at the connector/tool layer. No Claude-side invocation of the Opera tools has yet been observed in this campaign.

Therefore:

> **shared connector availability: observed**
>
> **shared browser-world perception by both minds: unproven**
>
> **autonomous cross-model coordination: unproven**

## Why this matters

If both minds can independently observe the same browser state, several SWM properties can emerge without building a shared database:

- one human/agent navigation can create an external trace visible to another;
- a tab can be a temporary shared referent;
- recent history can preserve weak continuity after a conversation ends;
- both minds can follow the same source door while keeping separate interpretation;
- one mind can create a new projection/tab and another can discover it;
- environment state can carry information without copying private chain/context between models.

This resembles the founding SWM goal:

> shared project reality, different minds.

It is also close to stigmergic coordination:
> participants alter or traverse an environment; later participants can use the resulting trace without direct addressing.

## Critical alternative explanations

A PASS must exclude weaker explanations:

- both models merely received the same prompt/context from the Owner;
- one model was told exactly which tab/page to inspect;
- browser history contains the answer as plain text and no environmental composition occurs;
- both connectors point to different browser sessions despite sharing the same provider name/server;
- one model sees stale tab state while the other sees current state;
- approval prompts make the Owner the real router;
- a task succeeds through model-native web/search rather than the shared Opera environment.

## Probe A — same-world identity

Goal: establish whether ChatGPT and Claude actually observe the same Opera instance/session state.

1. Create one uniquely named public test tab from one participant.
2. Do not tell the second participant the URL or title.
3. Ask only for its normal available browser-environment observation.
4. Qualify PASS only if it independently reports the unique tab from its Opera connector.
5. Reverse direction with a second unique tab.

No project content is needed.

## Probe B — environmental handoff without context copy

1. Mind A pursues a normal bounded task and opens a useful source/projection as a by-product.
2. Mind B starts with a related but separately phrased goal and no A transcript/handoff.
3. B may inspect ordinary Opera working-set traces.
4. Measure whether B notices and instrumentally reuses A's environmental trace.

Important:
- A must not encode an instruction to B in the tab title/page.
- B must not be told which tab is the donor.
- simple existence/navigation can be evidence; claimed comprehension needs source-level verification.

## Probe C — contradictory private interpretations over one shared object

1. Both minds inspect the same exact external object.
2. Each records its own local interpretation separately.
3. Neither interpretation is written back as the object's identity.
4. A later comparison asks whether shared referent identity remained stable while local meanings diverged.

This directly probes:
> same world / different minds.

## Probe D — stale observer state

Because earlier SWM/Reflex work found stale open-tab projections, deliberately test:
- one observer holding an old tab;
- another observer navigating fresh to the same source;
- source authority changing between observations.

Pass condition is **not** identical perception.

Pass condition:
> the environment lets each mind distinguish its observation freshness from source truth, or at minimum exposes enough evidence to detect the discrepancy without silently collapsing the two.

## Ecological success candidate

A stronger result would occur when, during real unrelated work:

- one model leaves a useful browser trace unintentionally;
- another later encounters it through normal working-set sensing;
- follows the authoritative source;
- and gains material value without Owner context transfer.

That would be stronger than an explicitly prompted shared-browser demo.

## Owner-orchestration boundary

Do not qualify a cross-model result if the Owner must:
- copy prompts/results between models;
- name the donor tab;
- repeatedly approve every required observation/action;
- explain what one model did to the other.

The current Claude tool-policy approval requirement therefore blocks a clean autonomous PASS unless it can be changed through normal product permissions or the experiment is explicitly scoped as a one-time body-calibration probe.

Do not ask the Owner to become the missing actuator merely to manufacture a result.

## Security/privacy boundary

The shared browser environment may contain unrelated private browsing.

For controlled experiments:
- use uniquely named public test pages/tabs;
- predeclare allowed domains/URLs for scoring;
- do not inspect unrelated history as semantic project context;
- record only the minimum evidence needed to establish shared-world behavior.

## Interpretation ceiling

Even a clean Probe A/B PASS would establish only:

> two heterogeneous model bodies can use one browser environment as a shared external observation/action substrate under the tested connector setup.

It would not establish:
- durable SWM architecture;
- cross-model trust;
- autonomous long-term collaboration;
- safe arbitrary shared browsing;
- lower Owner burden in general;
- that Slack is unnecessary;
- that browser state should become project authority.

The browser remains an environmental / working-set substrate. Project truth stays in project sources.

No feed, unread pressure or engagement mechanics were present.

On the richer object page it is possible to distinguish:

### Minimal object honesty

This remains a mechanical strength.

## Observed interaction friction

These findings come from the actual rendered surface, not from code aesthetics.

### F1 — Owner entry exposes technical kind too early

Root and Owner pages show:

- `Rodzaj deklarowany: browser/field-knot`
- `Deklarowany rodzaj: brak`

This is useful agent/debug metadata, but it is not needed to understand the thing as Owner.

It weakens progressive disclosure.

**Proposed smallest fix:** remove kind from Owner/root presentation; retain it in technical/raw view.

### F2 — rich Owner page becomes apparatus-heavy

All four local/participant records are expanded immediately.

Each exposes:

- semantic code;
- raw JSON link;
- full text.

The boundary between thing and meanings remains truthful, but the page feels like generated research apparatus rather than a calm place.

**Proposed smallest fix:** retain attribution/title + concise human-facing note on Owner surface; move semantic code/raw JSON under voluntary disclosure or technical depth.

### F3 — English participant perspective interrupts Polish Owner flow

The Browser participant perspective appears as a full English paragraph inside an otherwise Polish Owner surface.

The original participant text should remain exact and English.

But the Owner-facing page should not force the Owner to consume that language to understand the page.

**Proposed smallest fix:** Polish wrapper such as `Perspektywa uczestnika: Browser — oryginał po angielsku`; keep exact English perspective behind voluntary disclosure/raw link. Do not translate or replace the original automatically.

### F4 — minimal object looks like an empty schema/form

The minimal object renders separate headings for:

- Treść → brak
- Źródła → brak
- Powiązane… → brak

This is honest but visually/schema-heavy.

**Proposed smallest fix:** when all three are absent, show one compact Polish statement explaining that the thing currently declares only identity/raw metadata and that this absence is not an error.

### F5 — technical view has ambiguous duplicate raw record labels

Two independently owned records appear as:

`trace.json`  
`trace.json`

The links differ, but the visible labels do not.

This is real agent/debug friction.

**Proposed smallest fix:** technical list label includes source package slug or another already-known non-semantic package locator, e.g. `records-ba71… / trace.json`.

Do not infer Reflex/Combat semantics merely to improve the label.

## Non-problems / things not to "fix"

- Exact raw source having no Medium breadcrumb.
- Technical/raw view being English.
- The root explicitly saying global discovery is not designed.
- Minimal object having no human meaning beyond identity.
- Unknown semantic relation kinds remaining unstandardized.
- No search/feed/ranking.

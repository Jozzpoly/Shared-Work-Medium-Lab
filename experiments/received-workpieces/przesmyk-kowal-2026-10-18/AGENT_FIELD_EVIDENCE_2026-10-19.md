## 4. Trust boundary — a new role for *separate hosting origins*, not a mandate for Cloudflare

- Jaskinia and several labs currently share `https://jozzpoly.github.io` as one browser origin even though they use different repository paths. Standard browser storage isolation is by **scheme/host/port, not pathname**. A same-origin script can potentially read/modify the same origin's localStorage/IndexedDB, including imported Jaskinia materials. The exact Jaskinia embedding trust risk was already reported and should **not** be posted again as an independent new bug. No exfiltration or misuse observed. [MDN origin model](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy).
- A separate, trusted host for Jaskinia might make labs genuinely cross-origin while retaining links to their existing deployments: e.g. a dedicated Cloudflare Pages `<project>.pages.dev` origin (documented by Cloudflare), **or** a GitHub Pages custom subdomain if Owner already owns a suitable domain. This is a *candidate* for isolation, not evidence that either provider must be the platform substrate. [Cloudflare static deployment](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/), [direct upload](https://developers.cloudflare.com/pages/get-started/direct-upload/), [GitHub custom domains](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).
- **Critical counterpressure:** migrating origin **does not carry localStorage or IndexedDB bytes**. All authored notes, layouts and actual model blobs need a verified, complete, reversible export→restore transition, with the old origin preserved for recovery. Today Jaskinia layout snapshot is not a complete model-blob export. A rushed origin migration can irreversibly harm the very authoring continuity it aims to protect. Do **not** perform a migration, paid deployment or change Owner's working URL from this note.
